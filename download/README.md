# Downloads

This directory contains the two downloaders and the checksum manifest for the
evaluation subset. They are kept separate because they fetch very different
amounts of data.

| Script | Data | Size | Checksum |
|---|---|---|---|
| `download_evaluation_subset.sh` | The four objects, ground-truth meshes, paper weights and eight reconstructions needed to reproduce Table 4. | ~480 MB download, ~1 GB unpacked | `download/SHA256SUMS.txt` |
| `download_full_dataset.sh` | The full 616-object synthetic dataset used by the SHREC 2026 participants (one archive per category). | ~12.7 GB compressed, ~61 GB unpacked | `SHA256SUMS.txt` published in the Zenodo record |

## Evaluation subset (GRSI replication)

```bash
bash download/download_evaluation_subset.sh
```

The script reads the Zenodo record, archive name, direct URL and output
directory from `configs/experiment.yaml` (`data.zenodo_record`, `data.archive`,
`data.url`, `data.root`), verifies the archive against
`download/SHA256SUMS.txt`, and unpacks it into `data/SHREC2026_FACD_Table4/`.
Set `data.url` to the direct `.tar.gz` URL if the archive is not on Zenodo (for
example on Kaggle). Running the script again is a no-op if the data is already
present.

To use an archive that is already on disk:

```bash
SHREC_DATA_ARCHIVE=/path/to/SHREC2026_FACD_Table4.tar.gz \
    bash download/download_evaluation_subset.sh
```

`SHREC_ZENODO_RECORD_ID`, `SHREC_ZENODO_FILE`, `SHREC_DATA_ROOT`,
`SHREC_SHA256SUMS` and `SHREC_DATA_URL` override the corresponding values.

## Figure 1 data

The README teaser (paper Figure 1) is the weight map of
`90_1920x1080_relief_heightmap_1_one_face`, which is **not** one of the four
Table 4 objects in the evaluation subset. The mesh and its weights are included
in the repository as `sample/figure_01.tar.gz` (~13 MB compressed, ~76 MB
extracted), so `scripts/reproduce_figure_01.sh` can reproduce the exact figure
without the full dataset or a data download.

The script extracts the archive to a temporary directory, renders
`results/figure_01.png`, and compares it pixel by pixel with
`docs/teaser_250x250.png`. It also accepts the object from the full dataset
(`SHREC_FULL_DATASET=/path/to/3D_ground_truth_dataset`), and falls back to
`90_1920x1080_relief_heightmap_5_one_face_wide` from the evaluation subset with
a warning if neither is available.

## Full dataset

```bash
bash download/download_full_dataset.sh <ZENODO_RECORD_ID_OR_DOI> [OUTPUT_DIRECTORY]
```

Example:

```bash
bash download/download_full_dataset.sh 10.5281/zenodo.23584779 data/full_dataset
```

The full downloader follows the same manifest convention as the evaluation
subset: it downloads the record's `SHA256SUMS.txt` and verifies every archive
with it. It requires `jq` in addition to `bash`, `tar`, `sha256sum`, `curl` and
`md5sum`.

The same Zenodo record also contains `SHREC2026_FACD_Table4.tar.gz` (the
four-object evaluation subset); the full downloader downloads and extracts it
as well.

## Checksum manifest format

`SHA256SUMS.txt` uses the standard `sha256sum` format, one line per archive:

```
<sha256>  <filename>
```

The evaluation-subset manifest is committed here so that the Table 4
reproduction can verify the archive without trusting the download. The full
dataset's manifest is generated by the authors' upload script (not part of the
submission) and published in the Zenodo record.

## Updating the manifest

If the evaluation archive is rebuilt (for example after setting the license in
its `README.txt`), its SHA-256 changes. Update both manifests before publishing:

```bash
sha256sum SHREC2026_FACD_Table4.tar.gz
# replace the corresponding line in download/SHA256SUMS.txt
# and in the Zenodo record's SHA256SUMS.txt
```
